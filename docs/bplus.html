그대로 외우기

FASTQ → QC → 트리밍 → 얼라인먼트(BWA) → BAM → MarkDuplicates → BQSR → Variant calling(HaplotypeCaller) → VCF → Annotation(ANNOVAR)

단계왜 하나 (한 줄)
QC (FastQC)읽은 데이터가 쓸 만한지 확인 (Q30 기준)
트리밍 (cutadapt)어댑터·저품질 부분을 잘라낸다
얼라인먼트 (BWA)짧은 조각을 레퍼런스의 제자리에 맞춘다
MarkDuplicatesPCR 복사본을 빼서 변이 비율이 부풀지 않게
BQSR기계 품질 점수의 치우침을 바로잡아 에러를 변이로 착각하지 않게
Variant calling다른 곳 중 진짜 변이일 확률이 높은 것만 고른다
Annotation찾은 변이가 무슨 뜻인지 DB(ClinVar 등)와 연결

FASTQ→BAM = 전처리, BAM→VCF = 변이 발견. 교수님 문장 — "틀린 그림 찾기는 쉽다. 진짜 변이인지 계산하는 게 중요하다."

④ 서술형 6개 — 짧은 답 30분

하나씩 종이에 손으로 한 번 써 보세요. 아래 답을 가리고 쓰고, 맞춰 보면 돼요.

1. NGS란 무엇인가? (Sanger와 비교)

NGS는 DNA 조각을 판 위에 고정하고 염기를 합성하면서 동시에 형광으로 읽는(Sequencing by Synthesis) 기술로, 수억 개 조각을 한꺼번에 병렬로 읽는다. Sanger는 관 하나에 한 종류만 읽어 동시에 수십 개밖에 못 읽는다. 그 결과 사람 게놈 분석 비용이 30억 달러(13년)에서 약 200달러로 떨어졌다.

2. Illumina가 Roche를 이긴 이유는?

읽는 길이는 Roche(약 700)가 Illumina(약 150)보다 길었다. 하지만 Illumina는 처리량이 훨씬 커서 1Gb당 비용이 $7로 Roche($9,500)보다 1,000배 이상 쌌고 에러율도 0.1%로 낮았다. 결국 비용 때문에 Illumina가 시장을 차지했고 Roche는 2016년 문을 닫았다(기술 혁신은 비용과 연결된다).

3. Depth와 coverage의 차이, depth가 중요한 이유

Depth는 한 위치를 몇 개의 read가 겹쳐 읽었는지(예 30x), coverage는 레퍼런스 전체 중 한 번이라도 읽힌 비율(예 99%)이다. Depth가 높을수록 한 read의 에러를 다른 read가 보완해 진짜 변이와 시퀀싱 에러를 구별할 수 있다. 예를 들어 100x 중 1개만 다르면 에러지만, 2x에서 1개가 다르면 판단할 수 없다.

4. FASTQ에서 VCF까지 분석 순서와 각 단계의 목적

FASTQ → QC(품질 확인, Q30) → 트리밍(어댑터·저품질 제거) → BWA 얼라인먼트(레퍼런스 위치 찾기) → 정렬된 BAM → MarkDuplicates(PCR 중복 제거) → BQSR(품질 점수 보정) → HaplotypeCaller(진짜 변이일 확률 계산) → VCF → ANNOVAR(변이 의미 연결). FASTQ→BAM은 전처리, BAM→VCF는 변이 발견 단계이며, 단계마다 IGV와 coverage·depth로 확인한다.

5. MarkDuplicates와 BQSR은 왜 하나?

MarkDuplicates는 PCR 증폭으로 생긴 같은 조각의 복사본(시작·끝 위치가 같은 read)을 빼서 변이 비율이 부풀려지는 것을 막는다(단, amplicon 데이터는 생략). BQSR은 dbSNP 같은 알려진 변이 정보를 기준으로 기계 품질 점수의 치우침(bias)을 보정해, 시퀀싱 에러를 진짜 변이로 착각하지 않게 한다. 둘 다 정확한 variant calling을 위한 준비 단계다.

6. Variant calling에서 중요한 것은? (틀린 그림 찾기)

레퍼런스와 다른 곳을 찾는 것(틀린 그림 찾기)은 쉽지만, 그중에는 시퀀싱 에러가 섞여 있다. 그래서 핵심은 진짜 변이일 확률을 계산하는 것이다. GATK HaplotypeCaller는 변이가 몰린 active region에서 haplotype(함께 유전되는 변이 묶음)을 기준으로 확률을 계산해 확실한 변이만 VCF로 뽑는다.
