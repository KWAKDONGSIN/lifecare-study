BLAST에서 BWA로 — 왜 더 빠를까

BLAST(Basic Local Alignment Search Tool)는 옛날부터 쓰던 웹 검색 도구예요. 조각 몇 개를 찾기엔 좋지만, NGS의 수억 개 조각을 처리하기엔 너무 느려요.

그래서 빠른 aligner(얼라인 프로그램)가 아주 많이 나왔고, 대표가 BWA(Burrows-Wheeler Aligner)예요.

비유 — 포스트잇 색인

교수님 비유예요. 두꺼운 레퍼런스 책에 미리 포스트잇을 붙여 두면, 책을 처음부터 넘기지 않고 포스트잇으로 바로 찾아갈 수 있어요. 지도 앱에서 주소를 치면 그 위치로 바로 이동하는 것과 비슷해요.

BWA의 원리는 색인 + 씨앗 찾고 늘리기(seed-and-extend) 세 단계예요.

  1. 색인(index) 만들기 — 레퍼런스에 포스트잇을 미리 붙여요. 한 번만 하면 돼요. (bwa index)
  2. 씨앗(seed) 찾기 — 조각에서 짧은 10~20글자만 떼어, 포스트잇으로 후보 위치를 빠르게 찾아요.
  3. 늘리기(extend) — 후보 자리에서 양옆으로 늘려 가며 맞춰 보고, 점수로 최종 위치를 정해요.

이유는 간단해요. 책 전체를 처음부터 다 비교하지 않고 후보 몇 곳만 정밀하게 보기 때문이에요.

시험엔 이렇게 써요

BWA는 레퍼런스를 미리 인덱싱해 두고, read의 짧은 seed(10~20bp)로 후보 위치를 찾은 뒤 그 자리에서 extend하며 점수로 위치를 확정한다. 전체를 처음부터 비교하지 않기 때문에 BLAST보다 훨씬 빠르다.

잠깐 확인 — BWA의 "포스트잇"은 무엇을 가리키는 말일까요?

레퍼런스에 미리 만들어 둔 색인(index)이에요. 이것 덕분에 후보 위치를 바로 찾아가서 빨라요.
