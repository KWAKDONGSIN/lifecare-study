구간 A — 준비와 점검 (0~5단계)

본격적인 분석 전에 서버를 준비하고, 데이터가 쓸 만한지 확인하고, 불필요한 부분을 잘라 내는 단계예요.

단계도구넣는 것 → 나오는 것왜 하나요
0. 환경 준비ssh 접속, conda activate, 폴더 만들기실습 데이터 → 내 작업 폴더도구가 깔린 가상환경에 들어가야 해요. 안 들어가면 "도구가 없다"는 오류가 나요.
1. Base callingNGS 기기(Illumina 등)형광 이미지 → FASTQ (R1, R2)빛 사진을 ATGC 글자와 품질 점수로 바꿔요.
2. 품질 검사(QC)fastqcFASTQ → HTML 리포트데이터가 쓸 만한지 Q30 기준으로 봐요. 뒤쪽 점수가 떨어지면 어댑터를 의심해요.
3. 어댑터 트리밍cutadapt (변이 실습은 fastp)FASTQ → 트리밍된 FASTQ조각이 짧아 read에 딸려 온 어댑터와 뒤쪽 노이즈를 잘라 내요.
4. 페어드엔드 머지(연습용)pearR1 + R2 → 한 줄로 합친 긴 read겹치는 부분(overlap)으로 두 read를 이어 붙여요. 합쳐지지 않은 read는 따로 정렬하고, 변이 호출 스크립트에는 안 들어 있어요.
5. BLAST(웹 시연)NCBI BLAST 웹페이지짧은 서열 하나 → 일치하는 레퍼런스 목록local alignment가 어떤 모습인지 눈으로 봐요. NGS 대량 데이터에는 너무 느려요.
시험엔 이렇게 써요

FastQC로 FASTQ의 품질(Q30 기준)을 확인하고, 인서트가 read보다 짧아 섞여 들어온 어댑터와 저품질 구간을 cutadapt나 fastp로 트리밍한다. 트리밍하지 않으면 레퍼런스에 없는 서열이 정렬을 방해하고 변이로 오인될 수 있다.

잠깐 확인 — PEAR(머지)는 변이 호출 스크립트에 들어 있나요?

아니요. 6주차에 도구 하나씩 연습한 용도였어요. 변이 호출 스크립트는 fastp로 트리밍한 뒤 곧바로 정렬해요.
