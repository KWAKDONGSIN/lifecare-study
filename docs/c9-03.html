구간 B — 정렬 (6~12단계)

트리밍한 read를 레퍼런스 위의 제자리에 놓는 단계예요. 놓은 뒤에는 숫자와 눈으로 잘 됐는지 점검해요.

단계도구넣는 것 → 나오는 것왜 하나요
6. 레퍼런스 인덱싱bwa index (한 번만)레퍼런스 FASTA → 인덱스 파일들레퍼런스에 포스트잇을 붙여 두어 정렬이 빨라져요. 실습에서는 교수님이 미리 해 두었어요.
7. 얼라인먼트bwa mem (실습은 bwa-mem2)트리밍된 FASTQ + 인덱싱된 레퍼런스 → SAM짧은 read가 레퍼런스의 어느 위치인지 맞춰요(seed-and-extend).
8. SAM을 BAM으로samtools view -bSAM(텍스트, 큼) → BAM(이진, 작음)인간 유전체는 31억 염기라 SAM이 너무 커서 압축해요. 실습에서는 sort 단계에 합쳐졌어요.
9. 정렬(sort)samtools sortBAM → sorted BAM뒤죽박죽 순서를 염색체·위치 순으로 정리해요. 다음 단계와 IGV에 필수예요.
10. 인덱스samtools indexsorted BAM → .bai 파일BAM을 위치로 빨리 찾게 해 주는 색인이에요.
11. 통계 확인samtools flagstat, samtools coveragesorted BAM → 통계 텍스트붙은 read 수, duplicates, coverage, mean depth를 숫자로 확인해요.
12. 눈으로 확인IGV 웹앱sorted BAM + BAI → 화면read가 쌓인 모습과 레퍼런스와 다른 곳(색깔)을 눈으로 봐요.

실습에서는 7~9단계를 파이프(|)로 이어서 한 번에 했어요. 파이프는 앞 명령의 결과를 파일로 저장하지 않고 곧바로 다음 명령에 넘겨주는 거예요. 그래서 큰 SAM 파일이 중간에 안 생겨요.

비유

정렬(sort)은 도서관 책을 번호순으로 꽂는 일이고, 인덱스(.bai)는 "이 책은 몇 번째 칸"이라고 적은 목차예요. 목차가 있어야 원하는 위치를 바로 찾을 수 있어요.

시험엔 이렇게 써요

BWA는 레퍼런스를 미리 인덱싱하고 read를 짧은 seed로 쪼개 후보 위치를 찾은 뒤 확장하는 seed-and-extend 방식으로 정렬한다. 정렬 결과인 SAM을 BAM으로 바꿔 용량을 줄이고, 위치 순으로 sort한 뒤 index(.bai)를 만든다.

잠깐 확인 — 정렬 직후 samtools로 확인하는 숫자 두 가지는?

flagstat(붙은 read 수와 duplicates)과 coverage(coverage와 mean depth)예요. 실습에서는 coverage 99%, depth 약 20x가 나왔어요.
